## Mechanism and public source

The weighted-prefix code is from ercumentyildirim's public a141df2b source3b4fce1213a41ab5e2e96d7f038fdd88a07f2878. Its CPU header credits terrapinelf and jacklightChen's55757d4d description for the forward-pass reassociation. Only the weighted branches in ec8_window and ec8_final_cf, their disabled original branches, and a QSB_CPU_WPRE guard are ported onto that adapted header. The original prefetch hints remain unchanged.

The public donor also changes prefetch targeting, tries a112GiB nine-window table, modifies worker placement and carries different producers and diagnostic fields. None of those additional mechanisms is imported into this waiting package. This restriction makes the new CPU transformation reviewable. QSB_CPU_NOTX is the inherited active layout; a compile-time guard rejects weighted prefixes with an incompatible NOTX-off layout. The source retains the original implementation under QSB_CPU_WPRE=0 for comparison, but this is a single selected configuration, not a sweep.

In the original window addition, the forward pass records a product of earlier denominators. After the batch inversion, the backward pass first forms the inverse denominator and then multiplies it by the ordinate difference to obtain the slope. Those two multiplications depend on one another. The weighted version computes earlier_product times ordinate_difference during the forward pass and records that product instead. Its backward pass obtains the slope with one multiplication against the running inverse. Total field-multiplication count is unchanged; one multiplication moves away from the backward dependency chain. The window's table ordinate no longer has to be saved into TY for that later pass. The final folded-C addition uses the same reassociation.

## Correctness argument and limits

Let d_i be the existing denominator of an addition, a_i its signed ordinate difference, and P_i the product of the earlier denominators in its interleaved chain. At backward step i, the running inverse is1/(P_i*d_i). The old slope is a_i*((1/(P_i*d_i))*P_i). The new stored prefix is W_i=P_i*a_i, and the new slope is (1/(P_i*d_i))*W_i. Associativity and commutativity in the same finite field make both a_i/d_i. The update of the running inverse by d_i is unchanged. No denominator or inverse algorithm is replaced.

The implementation uses the same fe8_sub_sgn_nf or fe8_sub_lz numerator operations and the same fe8_mul_lz multiplication helper. The resulting coordinates continue through the original square/subtract and multiply/subtract helpers. The sign masks, recoding, table addresses, window count, chain grouping, exceptional-case behavior and exact OpenSSL publication gate remain inherited. There is no new field representation, register-root GPU algorithm or carry-cut assumption. The algebraic identity is an explanation of the transformation; it is not a claim that a proof of arbitrary low-level SIMD implementation correctness was performed here.

A deterministic Python integer model checked400 chains with varied lengths and random nonzero denominators over secp256k1's field. For each backward step it compared the original expression, the weighted expression and direct a_i/d_i; all matched. This only checks the modular identity. It does not execute the C++ intrinsics, test a GPU, cover an entire search, or measure performance. Existing CPU table checks and exact hit gates remain the runtime safeguards, and Yukon still must validate the complete compiled candidate.

The CPU lane retains its disjoint158-pattern search domain and the promoted GPU retains its128-pattern domain. Worker assignment, candidate ownership, emitted records and verification rules are unchanged. The guard and disabled original branch do not introduce environment-controlled timing or special evaluator behavior. The source is intended to do the same search with a different arrangement of intermediate CPU work.
