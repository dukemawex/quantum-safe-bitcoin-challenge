## Exact byte-layout argument

The base pointer is the existing saved state allocation, viewed as ulonglong2. For block index b and lane t, the original code computes st = saved + b*(QSB_STATE_PLANES*QSB_TREE_N) + t. This pointer is16-byte aligned because the allocation and each element have that alignment. The scalar view sw addresses eight uint64_t words in four pairs: offsets0/1,2*N/(2*N+1),4*N/(4*N+1),6*N/(6*N+1), where N isQSB_TREE_N. Multiplying these scalar offsets by8 gives the same byte positions as the four vector offsets0,N,2*N,3*N multiplied by16, plus the two in-vector word offsets0 and8.

The four new arguments are respectively(vbar[0],vbar[1]),(vbar[2],vbar[3]),(tbar[0],tbar[1]),(tbar[2],tbar[3]). Their order is unchanged. No intermediate value is rounded, reduced, transposed or recomputed. Each lane owns its existing distinct records; this optimization does not introduce shared writers. Prepare completion and the inherited stream dependencies already separate publication from finish consumption. Neither the original implementation nor this one relies on a128-bit atomic transaction for cross-kernel synchronization. The cache hint controls replacement preference, not the stored values.

The helper preserves all three inherited policy cases: cache-hinted evict-last when the native SM80 policy branch is enabled, plain vector global store for the ordinary state policy, and the existing qsb_st_v2 helper otherwise. The promoted native configuration usesQSB_L2STATE1033, and the regenerated carrier contains the intended cache-policy form. Full native regeneration matters here because the ranked path loads the embedded image; an unrebuilt carrier would leave the substantive device optimization inactive.
